# راهنمای سیستم مجوز (CMLicense)

## چطور کار می‌کند
در `index.html` ماژول `CMLicense` یک فهرست از هش‌های مجاز دارد. هنگام «ایجاد حساب»، `CMAuth.signup` اول `await CMLicense.isAllowed(code)` را صدا می‌زند؛ کد ملی با
`PBKDF2-HMAC-SHA256(password=کد ملی، salt=SALT، iterations=200000، keylen=32)` هش و با فهرست مقایسه می‌شود. اگر نبود، ساخت حساب رد می‌شود.
ورود (login) حساب‌های ساخته‌شده تغییری نکرده است.

## فروش به یک خریدار جدید
1. کد ملی را (فارسی یا انگلیسی) به `license-tools/buyers.txt` اضافه کنید. بعد از `#` می‌توانید نام/تاریخ بنویسید.
2. در پوشهٔ پروژه اجرا کنید:
   ```
   node license-tools/make-hashes.js --inject
   ```
   (Node.js نسخهٔ ۱۶ به بعد؛ بدون نصب پکیج.) هش‌ها داخل `index.html` بین `LICENSE-HASHES-START/END` جایگذاری می‌شوند.
3. نسخه را بالا ببرید و `version.json` را بسازید:
   ```
   node make-version.js 4.5.1 "افزودن مجوز جدید"
   ```
4. در `sw.js` عدد `CACHE_NAME` را یکی زیاد کنید (مثلاً `class-manager-v19`)، **قبل از** مرحلهٔ ۳ (چون هش `sw.js` در version.json ثبت می‌شود).
5. فایل‌ها را روی GitHub آپلود کنید.

## دستورهای ابزار
| دستور | کار |
|---|---|
| `node license-tools/make-hashes.js` | فقط `hashes.txt` را می‌سازد و بلوک را چاپ می‌کند |
| `... --inject` | علاوه بر آن، در `index.html` جایگذاری می‌کند |
| `... --check 0499370899` | هش یک کد را نشان می‌دهد و می‌گوید در `hashes.txt` هست یا نه |
| `--in / --out / --html / --salt` | تعیین مسیر ورودی، خروجی، index.html یا نمک |

ابزار کدهای نامعتبر (رقم کنترل غلط) و تکراری را گزارش و حذف می‌کند.

## تغییر نمک (قبل از فروش واقعی حتماً)
1. مقدار `SALT` را در `index.html` (داخل `CMLicense`) عوض کنید. ابزار نمک را خودکار از همان‌جا می‌خواند.
2. `node license-tools/make-hashes.js --inject` را دوباره اجرا کنید. **با عوض‌شدن نمک همهٔ هش‌ها باید دوباره ساخته شوند.**

## نکات مهم
- `buyers.txt` و `hashes.txt` در `.gitignore` هستند. فایل `buyers.txt` کد ملی خام دارد؛ آن را روی GitHub یا جای عمومی نگذارید.
- `isAllowed` نتیجه را به‌صورت Promise برمی‌گرداند (`await` لازم است).
- اگر فهرست خالی باشد هیچ‌کس نمی‌تواند حساب بسازد.
- روی https/localhost هش حدود ۰٫۳ ثانیه است. روی http غیرایمن (بدون WebCrypto) جایگزین JS به‌کار می‌رود و حدود ۱۰ ثانیه یا بیشتر طول می‌کشد.

## محدودیت‌های امنیتی (صادقانه)
- همه‌چیز سمت کاربر است: نمک و هش‌ها داخل `index.html` عمومی‌اند، پس «مخفی» نیستند. کسی که کد را ویرایش کند یا localStorage را دستکاری کند می‌تواند قفل را دور بزند. این سیستم جلوی استفادهٔ عادی/اشتراکیِ بدون مجوز را می‌گیرد، نه یک مهاجم مصمم.
- فضای کد ملی کوچک است (حدود ۱۰⁹ مقدار معتبر). کسی که فایل را دارد با کارت گرافیک می‌تواند در چند ساعت تا چند روز همهٔ هش‌ها را به کد ملی برگرداند. اگر محرمانگی کد ملی خریداران مهم است، به‌جای هش سمت کاربر از بررسی روی سرور استفاده کنید.
