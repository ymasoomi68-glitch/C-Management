# راهنمای مجوزها (CMLicense)

## اصل کار
- کد ملی خریدارها در `license-tools/buyers.txt` (فقط روی کامپیوتر شما) نگه داشته می‌شود.
- یک دستور، از روی آن فایل `licenses.json` (فقط **هش**‌ها) را در ریشهٔ پروژه می‌سازد.
- برنامه هنگام «ایجاد حساب» `licenses.json` را از اینترنت می‌خواند و هش کد ملی را با آن مقایسه می‌کند.
- پس برای افزودن/حذف خریدار **فقط `licenses.json` آپلود می‌شود**؛ `index.html`، `sw.js` و `version.json` و نسخهٔ برنامه تغییر نمی‌کند.

## افزودن کاربر جدید (گام‌به‌گام)
۱. در پوشهٔ پروژه (کنار `index.html`) یک دستور بزنید:
```
node license-tools/make-hashes.js add 0499370899 "نام خریدار"
```
(کد ملی فارسی هم قبول است؛ نام اختیاری است.) این دستور کد را اعتبارسنجی می‌کند، به `buyers.txt` اضافه می‌کند و `licenses.json` را می‌سازد.

۲. فایل `licenses.json` را در ریشهٔ مخزن GitHub آپلود (جایگزین) کنید. تمام.
   - اگر پوشه یک مخزن git است، همان دستور را با `--push` بزنید تا خودکار commit و push هم بشود:
   ```
   node license-tools/make-hashes.js add 0499370899 "نام خریدار" --push
   ```

۳. حداکثر ~۱۰ دقیقه بعد (کش GitHub Pages) خریدار می‌تواند حساب بسازد.

## دستورهای دیگر
| دستور | کار |
|---|---|
| `node license-tools/make-hashes.js` | فقط `licenses.json` را از `buyers.txt` می‌سازد (بعد از ویرایش دستی فایل) |
| `... add <کد> ["نام"]` | افزودن + ساخت |
| `... add` (بدون کد) | ساخت مجدد؛ برای وقتی چند خط را دستی به `buyers.txt` اضافه کرده‌اید |
| `... remove <کد>` | حذف + ساخت |
| `... list` | فهرست خریداران |
| `... check <کد>` | آیا در `licenses.json` هست؟ |
| `--push` | بعد از ساخت، git add/commit/push |

## نکات
- حذف یک کد فقط **ساخت حساب جدید** را می‌بندد؛ حسابی که قبلاً روی دستگاه ساخته شده کار می‌کند.
- اگر خریدار هنگام ساخت حساب اینترنت نداشته باشد، از آخرین فهرستِ موفقِ ذخیره‌شده استفاده می‌شود؛ اگر هیچ‌وقت فهرست نگرفته باشد پیام «اتصال اینترنت لازم است» می‌بیند.
- `buyers.txt` و `.hash-cache.json` را روی GitHub نگذارید (در `.gitignore` هستند). `licenses.json` عمومی و فقط هش است.
- ساخت مجدد سریع است: هش‌های قبلی در `.hash-cache.json` ذخیره می‌شوند (هر کد جدید حدود ۰٫۱ ثانیه).

## تغییر نمک (فقط یک بار، قبل از فروش واقعی)
۱. مقدار `SALT` را در `index.html` (داخل `CMLicense`) عوض کنید؛ ابزار آن را خودکار از همان‌جا می‌خواند.
۲. `node license-tools/make-hashes.js` را بزنید و این‌بار `index.html` و `licenses.json` را هر دو آپلود کنید (نسخه را یک‌بار بالا ببرید). بعد از این، دیگر هرگز نمک را عوض نکنید، وگرنه همهٔ هش‌ها نامعتبر می‌شوند و باید دوباره ساخته شوند.

## محدودیت‌های امنیتی
- همه‌چیز سمت کاربر است؛ نمک و هش‌ها عمومی‌اند. کسی که کد را ویرایش کند می‌تواند قفل را دور بزند. این سیستم جلوی استفادهٔ اشتراکیِ عادی را می‌گیرد، نه یک مهاجم مصمم.
- فضای کد ملی کوچک است (~۱۰⁹ مقدار معتبر)؛ کسی که `licenses.json` و نمک را دارد با کارت گرافیک می‌تواند هش‌ها را به کد ملی برگرداند. اگر محرمانگی مهم است، بررسی باید روی سرور انجام شود.
